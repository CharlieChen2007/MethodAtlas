## 2. 关键设计决策

### 2.1 7 步 ≠ 6 视图，必须分开建模

导航条是 **7 步**（含「论文」），右侧工具栏是 **6 视图**（不含「论文」，
因为论文是"输入源"不是"视图模式"）。两者**不是超集关系**，因此：

```ts
export const WORKFLOW_STEP_IDS = ['paper','dna','surgery','evolution','debt','idea','crashtest']  // 7
export const VIEW_IDS = ['dna','surgery','evolution','debt','idea','crashtest']                  // 6
export function viewOfStep(id: WorkflowStepId): ViewId | null {
  return id === 'paper' ? null : id      // 论文没有对应视图
}
```

「论文」这一步点击的行为 = **触发上传入口**
（`document.getElementById('lab-upload-input')?.click()`），不切视图。

### 2.2 状态判据 = 数据库实际数据，不是"访问过"

产品原话：「状态根据数据库实际数据判断（比如 Surgery 表有记录 = 手术步骤完成）」。
所以 7 步的 `done` 判据是：

| 步骤 | 判据 |
|------|------|
| 论文 | `papers.length > 0` |
| 方法 DNA | `structuredPaperCount(data) > 0`（至少 1 篇有 MethodBlock） |
| 方法手术 | `surgeries.length > 0` |
| 方法演化 | `relations.length > 0` |
| 研究债务 | `debts.length > 0` |
| 组合想法 | `ideas.length > 0` |
| 击穿测试 | `crashTests.length > 0` |

> 注意 `dna` 用的是「**有结构的论文**数」而不是「论文数」——
> 否则上传一篇还没抽取的 PDF，「方法 DNA」就会假装已完成。

### 2.3 ★ 与 → 同时标（产品确认过的口径）

- `★` = **当前视图**（用户此刻在看哪一步）
- `→` = **建议下一步**（第一个未完成的步骤）

两者是**不同维度**：可能同一步（当前视图也是第一个未完成），
也可能不同（当前视图是已完成的 DNA，而建议去做手术）。
产品明确要求「两者都标」，所以 `stepMark()` 返回 `{state, stateSymbol, roleSymbol, stateText}` 四元组。

### 2.4 上下文横条与 cornerNote 分开

`getAvailability` 给的 `cornerNote` 是**静态数据建议**；
上下文横条是**跨步骤传来的动态上下文**。语义不同，所以放独立槽位，
不污染 `getAvailability` 的契约。

### 2.5 颜色：导航条刻意用单一强调蓝

视图色（右栏）/ 阶段色（画布节点）/ 状态色（卡片徽标）是**三层隔离**的。
导航条如果给 7 步各配一种颜色，就是引入**第四层**，会破坏隔离契约。
所以导航条统一用一个强调蓝 `#2563eb` 表示"当前"，
其余用中性灰阶表示完成/未开始。

## 3. 踩过的坑（都写进了代码注释）

### 3.1 `min-h-0` 是硬要求

`[pid]/lab/layout.tsx` 是 `h-screen w-screen overflow-hidden`。
LabShell 改成 `flex flex-col`（导航条 + 主体行）之后，主体行是 flex item，
默认 `min-height: auto` —— 右栏的论文切换器是 `flex-1 overflow-y-auto`，
会**顶开父级高度** → 整页出现滚动条 → 验收 4/5 直接失败。

修法：`<div className="flex min-h-0 w-full flex-1">`。

### 3.2 验收脚本的 `.flex.h-full.w-full` 选择器被打歪

验收 5 用 `document.querySelector('.flex.h-full.w-full')` 定位"画布 + 工具栏"这一层算宽度占比。
P7-4 加了顶部导航条后，**外层** `<div className="relative flex h-full w-full flex-col">` 先被命中，
它的第一个孩子是**隐藏的 `<input>`（宽度 0）**，
于是占比算成「画布 0% / 工具栏 100%」——纯假失败。

修法：给主体行加语义化 `data-lab-body`，脚本改用它定位。**契约钉死，不再靠 class 猜。**

### 3.3 验收脚本"取最长中文行"拿按钮标签被打歪

验收 2 从每个工具栏按钮的 `innerText` 里**取最长的那行**当标签，再和 `VIEWS` 比对。
P7-4 给按钮加了「第 N 步 · 已完成」这一行 —— 它比「方法 DNA」长，
于是取到的是状态文案，6 个按钮一个都对不上。

修法：不再猜哪行是标签，直接返回全部行，Python 侧按 `VIEWS` 白名单匹配。

### 3.4 验收脚本硬编码坐标点空白处被打歪

验收 9 跑完手术后要点画布空白**取消选中**，否则被干预节点还挂着蓝框
（选中态优先级高于干预红框，这是设计如此），永远量不到红。
脚本写死了 `(360, 120)`。P7-4 顶部多了 55px 导航条，画布整体下移，
这个点现在**落到节点上** → 点它反而选中了节点 → 红框被蓝框吃掉 → 断言假失败。

修法：改成"扫描画布，找一个确实不被任何节点覆盖的点"，并且**循环最多 3 次
直到确认无节点处于选中态**——不碰运气。

### 3.5 跨时刻快照比对必然对不上

验收 10 一开始把 10.2 抓的导航条状态（此刻视图 = DNA）和 10.6 抓的工具栏状态
（此刻视图 = debt）对比"current 是否一致"——两个不同时刻的快照，
`current` 当然会漂移。修法：**同一时刻重抓两边**再比。

### 3.6 验收 10 不能假设 demo 基线

验收 9 会**真的跑一次方法手术**（往 Surgery 表写一行）。
所以轮到验收 10 时 `Surgery=1`，"手术"这一步应当是 `done` 而不是 `todo`。
初始版本把期望写死成 `todo`，被自己的前置步骤打脸。

修法：加 `db_counts()` 直接查库拿真值，再拿它对照界面状态 ——
**这才真正验证了"状态由数据判断"这件事**，而不是把答案写进断言里。

### 3.7 预填提示显示 cuid 是丑陋的

上下文继承链 ① 原本把 `prefillDebtId` 直接打进提示文案，
屏幕上显示「已带上目标债务「cmu721sla000awcmmaru3ulrn」」——
用户看不懂 cuid。修法：改成传 `contextDebtTitle`，
提示显示「已带上目标债务「计算开销与可扩展性」」。

### 3.8 状态条字号量错层

验收 10 量状态条第二行字号时，取的是 `children[1].querySelector('span')` ——
那是 `flex items-center gap-1` 的**布局 wrapper**，没有自己的 `text-*` class，
`getComputedStyle` 返回继承来的 16px（假数据）。
修法：取该行**所有叶子文本节点**里最大的字号。
