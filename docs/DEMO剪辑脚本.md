## ⚠️ 勘误（两次）

**v1** 写进了 `07:42`、`08:25`、`08:47` 这类时间码 —— **视频只有 5:27，不存在 7 分钟以后的画面**。
原因：我按"预期演示流程"估时间点，那份错误段表总和是 527 秒。更糟的是，我只在文末写了句
"多出 200 秒"，**正文表格和 ffmpeg 命令里的错误时间码一个都没换**，等于把错误又交付了一次。

**v2** 我把结尾段当成"05:00–05:27 = 现场运行 + 报告 + 综合判定"。**这也是错的**：
打开 `0325.jpg` 一看，05:25 画面已经**回到 DNA 视图**了，并不是停在击穿报告上。

**v3 的做法（为了不再犯）**：时间点不再手写，改成由脚本从**抽帧产物**里读，并加硬校验：

```
抽帧秒数范围: 0 → 325（共 66 帧）
实测视频时长: 6791 帧 ÷ 20.737 fps = 327.5s
每段源区间必须：① 在 327s 内  ② 区间内至少有一帧抽帧作为证据
→ 校验结果：越界 0 段，无证据 0 段 ✅
```

## 三、ffmpeg 命令（方案 A · 已校验）

> **每条都在 0–327 秒内。** 把 `input.mp4` 换成源文件路径，路径含空格/中文要加引号。

```bash
# 01 开场页  1.0x  10.0s
ffmpeg -ss 0 -to 10 -i "input.mp4" -vf "setpts=PTS/1.0" -an -c:v libx264 -crf 20 -preset medium seg01.mp4

# 02 DNA 画布 + 看板  1.6x  12.5s
ffmpeg -ss 10 -to 30 -i "input.mp4" -vf "setpts=PTS/1.6" -an -c:v libx264 -crf 20 -preset medium seg02.mp4

# 03 模块详情  1.5x  13.3s
ffmpeg -ss 30 -to 50 -i "input.mp4" -vf "setpts=PTS/1.5" -an -c:v libx264 -crf 20 -preset medium seg03.mp4

# 04 方法手术  1.8x  16.7s
ffmpeg -ss 50 -to 80 -i "input.mp4" -vf "setpts=PTS/1.8" -an -c:v libx264 -crf 20 -preset medium seg04.mp4

# 05 手术结论面板  1.5x  12.0s
ffmpeg -ss 80 -to 98 -i "input.mp4" -vf "setpts=PTS/1.5" -an -c:v libx264 -crf 20 -preset medium seg05.mp4

# 06 演化时间线 8 行  1.5x  20.0s
ffmpeg -ss 135 -to 165 -i "input.mp4" -vf "setpts=PTS/1.5" -an -c:v libx264 -crf 20 -preset medium seg06.mp4

# 07 演化：右栏论文详情  1.6x  14.4s
ffmpeg -ss 165 -to 188 -i "input.mp4" -vf "setpts=PTS/1.6" -an -c:v libx264 -crf 20 -preset medium seg07.mp4

# 08 研究债务  1.5x  15.3s
ffmpeg -ss 195 -to 218 -i "input.mp4" -vf "setpts=PTS/1.5" -an -c:v libx264 -crf 20 -preset medium seg08.mp4

# 09 组合想法工作台  1.6x  23.8s
ffmpeg -ss 220 -to 258 -i "input.mp4" -vf "setpts=PTS/1.6" -an -c:v libx264 -crf 20 -preset medium seg09.mp4

# 10 组合想法：完成勾选  1.8x  15.0s
ffmpeg -ss 258 -to 285 -i "input.mp4" -vf "setpts=PTS/1.8" -an -c:v libx264 -crf 20 -preset medium seg10.mp4

# 11 击穿：报告与 AI 结论  1.3x  10.8s
ffmpeg -ss 300 -to 314 -i "input.mp4" -vf "setpts=PTS/1.3" -an -c:v libx264 -crf 20 -preset medium seg11.mp4

# 12 击穿：判定 + 看板分布  1.3x  10.0s
ffmpeg -ss 314 -to 327 -i "input.mp4" -vf "setpts=PTS/1.3" -an -c:v libx264 -crf 20 -preset medium seg12.mp4
```

### 拼接

```bash
: > list.txt
for i in 01 02 03 04 05 06 07 08 09 10 11 12; do
  echo "file 'seg$i.mp4'" >> list.txt
done
ffmpeg -f concat -safe 0 -i list.txt -c copy cut_nosound.mp4
```

### 铺配音 + 导出

```bash
ffmpeg -i cut_nosound.mp4 -i voiceover_full.wav \
  -c:v copy -c:a aac -b:a 192k -shortest final.mp4

ffmpeg -i final.mp4 -vf "scale=-2:1080:flags=lanczos" \
  -c:v libx264 -crf 20 -preset slow -pix_fmt yuv420p \
  -c:a aac -b:a 192k -movflags +faststart "MethodAtlas-DEMO.mp4"
```

- `-an`：丢弃原声（原片音轨只有环境噪声与点击声）。要保留就换成 `-af "volume=0.05"`。
- `scale=-2:1080`：宽度自适应，避免 2416×1440 → 1920×1080 的轻微拉伸。
- 铺配音建议用剪辑软件：把 12 段旁白按配音稿给的时间点拖到位，比命令行对齐省事。

## 五、教训

1. **时间码从素材里读，不能凭演示脚本估。** 做法：每 5 秒抽一帧、烧上时间戳、
   拼 contact sheet，再逐格读；或直接 `帧数 ÷ fps` 算总长。
2. **发现矛盾必须回头改正文。** v1 承认了"多出 200 秒"却没换掉表格与命令里的错误时间码，
   等于把错误又交付了一次 —— 这是这次最该改的习惯。
3. **不要用"我以为的画面"去写时间轴。** v2 的结尾段就是想象出来的。
   打开 `0325.jpg` 看一眼，5 秒就能发现它已经回到 DNA 视图了。
