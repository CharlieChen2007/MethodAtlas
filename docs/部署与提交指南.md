# 在线部署指南（含「让 AI 真的能用」的关键配置）

> 目标：**外部访问者打开链接，AI 分析 / AI 对话能真的跑起来**，而不是降级成演示数据。
>
> 这份文档里的每条结论都在本机实测过，不是照抄平台文档。

---

## 一、先说结论：选什么平台

### ❌ 不要用 Vercel

两个硬冲突，任何一个都会让"AI 真能用"落空：

| 冲突 | 后果 |
|---|---|
| **数据库是 SQLite 单文件** | Vercel 的 Serverless 磁盘是临时的，写入下次请求就没。评委看到空库 |
| **单次 AI 分析最长要 2–4 分钟**（`LLM_TIMEOUT_MS` 默认 120s、总预算 240s） | Vercel Hobby 函数上限 10s、Pro 默认 60s。必被掐断 → 报错或降级 mock |

实测依据：`src/lib/llm.ts` 里单次请求超时 120000ms、整链总预算 240000ms；
而 Server Action **无法声明 `maxDuration`**，所以没法给"抽 DNA / 演化 / 债务 / 击穿"
这些长链路单独放宽时限。

### ✅ 用带持久磁盘的容器型平台

| 平台 | 持久磁盘 | 长请求 | 备注 |
|---|---|---|---|
| **Railway** | ✅ Volume | ✅ 无硬超时 | 最省事，中文文档少；有免费额度但会扣费 |
| **Render** | ✅ Disk | ⚠️ 免费实例会掐长连接 | **付费实例**才稳；免费档不适合本项目的长链路 |
| **Fly.io** | ✅ Volume | ✅ | 配置略繁琐 |
| **自己的云主机 / 校内服务器** | ✅ 就是本地磁盘 | ✅ | **最稳**，评委用的正是这个链接；配合 `docker run` 即可 |

**推荐**：如果学校/实验室有服务器 → 直接 Docker 跑（最稳、无平台限额）。
没有的话 → **Railway**（最省事）。

## 二、让 AI 真能用的环境变量（**在平台控制台填，不要提交进仓库**）

密钥进仓库是撤不回来的（git 历史追加式，且公开仓库会被爬虫秒级扫走）。
所有平台都有「Environment / 环境变量」界面，填在那里即可 —— 不进任何文件。

```
# ① 数据库（SQLite 落持久盘；用**绝对路径**，相对路径的坑见 README 部署章节）
DATABASE_URL=file:/data/dev.db

# ② 真模型（这四条是「AI 真能用」的关键）
LLM_PROVIDER=openai-compatible
LLM_MODEL=deepseek-chat
LLM_API_KEY=<在这里填你的 key>
LLM_BASE_URL=https://api.deepseek.com/v1

# ③ 文件存储（上传的 PDF 也落持久盘）
STORAGE_DIR=/data/storage

# ④ 分享域名（**必填，否则 Server Action 全被拒**）
#    填平台的公网域名，不带 https://
NEXT_PUBLIC_APP_ORIGIN=your-app.up.railway.app
```

### ⚠️ 少配 `NEXT_PUBLIC_APP_ORIGIN` 会怎样

Next.js 对 Server Action 有 CSRF 防护，默认只信任 localhost。
不配这个变量时：**首页 `curl` 是 200（看着像部署成功），但一点按钮就
"Invalid Server Actions request" 变成 Application error** —— 最难查的一类故障。
`next.config.mjs` 里已经留好这个开关，填域名即可。

### 验证 AI 真的接上了

**用项目自带的连通性自检**（只读、不启服务、不写库）：

```bash
node scripts/llm-check.mjs
```

它直接拿 `.env` 里的配置**调一次真实接口**，把 HTTP 状态、耗时、token 用量、
模型回答原样打出来；退出码 `0` = 连通，`1` = 不通（原因也在输出里）。
临时换 key 试：`node scripts/llm-check.mjs --key sk-xxx`（不写盘）。

> ⚠️ **不要用 `/api/llm-status` 判断密钥配没配。**
> 我一开始也是这么写的，后来实测发现该接口返回的是
> `{degraded, degradedReason, successCount, degradedCount, tokens, byPurpose}`
> —— **没有 `provider` 字段**。它回答的是"调用**失败过**没有"，
> 不回答"用的是 mock 还是真模型"。配置成 `LLM_PROVIDER=mock` 时它同样是
> `degraded: false`（因为根本没发生"失败降级"），照它判断会得出错误结论。

另外两个能看出来的地方：

- **画布右上角的「离线模式」徽标**：只在**真模型调用失败并降级**时出现
  （悬停会显示具体原因）。它**不覆盖**"本来就配成 mock"这种情况。
- **跑一次真实动作后的产出**：真模型的结论会带具体机制描述；
  mock 的产出会被标成「证据有限」。若配成 mock，服务端日志里也会看到
  provider 为 mock。

## 三、部署步骤（Docker 路线，平台通用）

仓库里已备好 `Dockerfile` + `docker-entrypoint.sh`，所以**不需要在平台上配构建命令**。

### 3.1 本机自测镜像（强烈建议先跑一遍）

```bash
docker build -t methodatlas .
docker run -p 3000:3000 \
  -e DATABASE_URL="file:/data/dev.db" \
  -e LLM_PROVIDER=openai-compatible \
  -e LLM_MODEL=deepseek-chat \
  -e LLM_API_KEY=<你的key> \
  -e LLM_BASE_URL=https://api.deepseek.com/v1 \
  -e NEXT_PUBLIC_APP_ORIGIN=localhost:3000 \
  -v methodatlas-data:/data \
  methodatlas
```

打开 `http://localhost:3000` → 应看到 8 篇论文的演示数据，且**无「离线模式」徽标**。

### 3.2 推到平台

1. 把仓库 push 到 GitHub/Gitee（见第四节）
2. 平台选「Deploy from GitHub repo」
3. 有 Dockerfile 时平台会自动识别为 Docker 部署
4. 在平台控制台**加持久卷**，挂载到 `/data`
5. 按第二节填环境变量（**密钥填在平台界面**）
6. 首次部署完成后点一次「Redeploy」让环境变量生效

> **为什么镜像里自带演示数据**：`docker-entrypoint.sh` 首次启动会把镜像内的
> 种子库复制到 `/data/dev.db`。这样评委打开链接**立刻**看到 8 篇论文的完整
> 流水线结果（DNA / 演化 / 债务 / 想法 / 击穿报告），而不是空库等你现场跑
> 20 分钟抽取。

## 四、源码仓库（GitHub / Gitee）

### 4.1 仓库里有什么、没有什么

| 内容 | 是否入库 | 原因 |
|---|---|---|
| 全部源码 `src/`、`scripts/`、`prisma/schema.prisma` | ✅ | 组委会要的"完整源码" |
| `package-lock.json` | ✅ | 保证依赖可复现 |
| `.env.example` | ✅ | 环境变量模板（**不含真密钥**） |
| `prisma/dev.db` | ✅ **已强制加入** | 演示数据；不带它在线链接是空库 |
| `storage/papers/*.pdf`（8 份） | ✅ **已强制加入** | 证据抽屉要读原文；不带它"查看证据"打不开 |
| `.env` | ❌ **不入库** | 含真密钥，见第二节 |
| `node_modules/`、`.next/` | ❌ | `.gitignore` 已排除 |

> `prisma/dev.db` 与 `storage/papers/` 本来被 `.gitignore` 排除（本意是别误提交本地数据），
> 但它们是**演示资产**，所以用 `git add -f` 强制加入了。
> 已用 `tools/check-db-clean.py` 扫过：**库里无 API Key、无本机绝对路径**。

### 4.2 推送命令

```bash
cd methodatlas
git add -A
git commit -m "MethodAtlas：8 篇 Wi-Fi 指纹数据增强语料的完整流水线演示"
git branch -M main
git remote add origin https://github.com/<你的账号>/methodatlas.git
git push -u origin main
```

> Gitee 同理，把 remote 换成 Gitee 地址即可。
> 首次 push 会要凭据：GitHub 现在**不接受密码**，要用 **Personal Access Token**
> （Settings → Developer settings → Tokens，勾 `repo` 权限）。

### 4.3 push 之前自己再扫一遍密钥

```bash
# 仓库内容自查（含 git 历史）
git log -p | grep -nE '(?<![A-Za-z])sk-[A-Za-z0-9_-]{16,}' || echo "干净"
# 演示库自查
python tools/check-db-clean.py
```

## 五、公网暴露的**成本风险**（请务必读）

在线链接一旦公开，**任何人都能点"抽取方法结构 / 运行击穿测试"** ——
每次都会真实调用模型、消耗你的额度。这不是危言耸听，是本项目当前设计的直接后果：
`/api/pipeline` 默认关闭且无鉴权（已按安全默认处理），但**界面上的按钮是开着的**。

建议至少做一条：

| 做法 | 效果 | 改动量 |
|---|---|---|
| **给链接加访问口令**（平台自带的 Basic Auth / Access Control） | 只有知道口令的人能进 | 平台侧配置，零代码 |
| **用额度很低的 key** 并设置消费上限 | 被刷也损失有限 | 控制台设置 |
| 演示期临时开、录完视频就下架 | 最省 | — |

> ⚠️ 请**不要**把 key 写进前端代码或 `NEXT_PUBLIC_*` 变量 ——
> `NEXT_PUBLIC_` 前缀的东西会打包进浏览器代码，等于公开。
> 本项目所有模型调用都在服务端（Server Action / API Route），前端拿不到 key。
