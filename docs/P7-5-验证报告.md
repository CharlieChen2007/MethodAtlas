## 1. 缺陷 1：底部详情面板遮挡操作按钮

### 根因

操作入口同时存在于两处：

- `ActionBar`（画布上，`z-30`）
- `BottomPanel`（底部，`z-20`，高 `38vh`）

面板滑出时覆盖画布下沿，画布上的按钮虽然 `z-30` 高于面板 `z-20`，但**面板滑出的那块区域把画布视觉遮住了**，用户看到的"手术按钮"实际落在面板背后，观感上就是"被遮住"。

### 修法

**把操作入口全部收进底部详情面板**，画布上只保留节点与连线。

- 画布上不再挂操作按钮（只有节点 / 连线 / 空态提示块）。
- 节点被点击 → 底部面板滑出 → 面板底部 `footer` 内是该节点**全部可用动作**（查看证据 / 以此为起点做手术 / 撤销本次手术）。
- 空态提示块（`EmptyCanvas`）在面板滑出时**主动上移避让**：新增 `liftedByPanel` prop，`transform: translateY(calc(-38vh + 6px))`。

### 影响范围

`src/lib/lab/panel.ts`（动作列表定义）、`src/components/lab/BottomPanel.tsx`（动作渲染 + `data-panel-action` 钩子）、`src/components/lab/EmptyCanvas.tsx`（避让）、`src/components/lab/LabShell.tsx`（传 `panelOpen`）、`src/components/lab/CanvasStage.tsx`（转发 `panelOpen`）。

## 2. 缺陷 2：手术不可逆

### 根因

不是后端缺陷。`deleteSurgeryAction` 已实现且真删库：

```ts
// src/lib/actions/lab-actions.ts:93
export async function deleteSurgeryAction(surgeryId: string) {
  await prisma.surgery.delete({ where: { id: surgeryId } })   // ← 真删
  revalidatePath(...)
  return { ok: true, message: '已删除该手术记录' }
}
```

**缺的是 UI 出口**：面板里没有这个按钮，也没把"surgeryId"传到前端。

### 修法

1. `PanelContent` 新增 `undoSurgeryId?: string`；
2. `buildPanelContent` 在 block 节点分支里，找到**最近一次**干预该 Block 的手术：

```ts
const lastSurgery = [...data.surgeries]
  .reverse()
  .find((s) => s.intervenedBlockIds.includes(b.id))
```

3. 有则注入 `{ label: '撤销本次手术', kind: 'undoSurgery' }` 并附「最近一次手术」正文；
4. `LabShell.handlePanelAction` 新增 `case 'undoSurgery'`，调 `deleteSurgeryAction(surgeryId)`，成功后 `refreshData()`。

**「同一 Block 被多次手术，只撤销最近一次」** 由 `[...surgeries].reverse().find(...)` 保证 —— 永远取时间上最后一条。

### 影响范围

`src/lib/lab/panel.ts`、`src/components/lab/LabShell.tsx`。**后端 0 改动**（复用既有 action）。

## 3. 缺陷 3： 「运行演化分析」按钮是死的

### 先回答那三个问题（产品负责人点名要的）

**Q1：`evolutionAction` 是否真的存在？在哪个文件？**

存在。`src/lib/actions/lab-actions.ts:113`：

```ts
export async function evolutionAction(projectId: string) {
  const res = await extractEvolution(projectId)   // src/lib/method-evolution.ts
  await guardRelationWrites(projectId)
  revalidatePath(...)
  return { ok: true, message: `建立 ${res.created} 条演化关系，${res.evidence} 条证据…` }
}
```

**Q2：函数体是什么？有没有真的调用后端 pipeline？**

真的调。调用链：`evolutionAction` → `extractEvolution` → 读库里的 `MethodDNA` → mock LLM 抽取 5 类关系 → **写库**：

```ts
// src/lib/method-evolution.ts
await prisma.relation.deleteMany({ where: { projectId } })   // L270 先清
...
await tx.relation.create({ data: { ... } })                  // L403 再写
```

**Q3：`relations.length === 0` 时点它，会不会真的往 Relation 表写？还是只切视图？**

**真的往 Relation 表写。** 实测 `relation 0 → 2`。它**不是**切视图 —— 这一点在修好事件模型后，浏览器网络面板里能看到真实的 Server Action POST。

> ⚠️ 注意：这个按钮**只在 `relations.length === 0` 的空态下渲染**。所以"按钮是死的"这个症状，只在空态可复现 —— 与产品负责人描述一致。

### 根因（这是四个缺陷里唯一的**真 bug**）

**不是没接线，不是被遮挡，是 `click` 事件从未被派发。**

诊断过程：在空态下给按钮挂探针 `window.__ev = ['pointerdown','mousedown']` —— 结果**没有 `click`**。

原因在 `CanvasStage`：`onPointerDown` 里立刻 `setPointerCapture()`。指针捕获会把它之后**所有**指针事件都重定向到捕获元素（画布容器），于是画布内部按钮的 `pointerup` 收不到配对 → 浏览器判定这不是一次完整点击 → **不派发 `click`**。

按钮既没被遮挡、也不是没接线 —— 它被自己的父容器"吞"掉了事件。

### 修法：两段式指针捕获

```ts
const onPointerDown = (e) => {
  if (e.button !== 0) return
  dragRef.current = { active:true, moved:false, startX:e.clientX, ... }
  // ⚠️ 此处刻意【不】setPointerCapture
}

const onPointerMove = (e) => {
  const d = dragRef.current
  if (!d?.active) return
  const dx = e.clientX - d.startX, dy = e.clientY - d.startY
  if (!d.moved && Math.hypot(dx, dy) > DRAG_THRESHOLD) {   // DRAG_THRESHOLD = 4px
    d.moved = true
    e.currentTarget.setPointerCapture?.(e.pointerId)        // ← 确认是拖拽了才捕获
    setDragging(true)
  }
  if (d.moved) setOffset(clampOffset(d.originX + dx, d.originY + dy))
}

const onPointerUp = (e) => {
  const d = dragRef.current; dragRef.current = null; setDragging(false)
  if (d?.active && d.moved) { e.currentTarget.releasePointerCapture?.(e.pointerId); return }
  if (d?.active && !d.moved) onBackgroundClick?.()          // 没超过阈值 = 点空白
}
```

**点按钮**：位移为 0，从不捕获，`click` 正常触发。
**拖画布**：一旦超过 4px 就捕获，指针移出画布也不丢事件。
**点空白**：未超阈值 → 交给 `onBackgroundClick`（关面板）。

### 影响范围

`src/components/lab/CanvasStage.tsx`（拖拽三分支重写）。**这一处同时修好了缺陷 3 和缺陷 4 的一半**（光标状态也在这里）。

### 验证

## 4. 缺陷 4：画布拖拽变成选文字

### 根因

画布容器没有压制文字选择，拖拽时浏览器把它判定为"划选文本"；光标也全程是默认箭头，没有"可拖拽"的暗示。

### 修法

```ts
// CanvasStage 容器 style
cursor: dragging ? 'grabbing' : 'grab',
userSelect: 'none',
WebkitUserSelect: 'none',   // Safari 仍需前缀版
touchAction: 'none',        // 触摸侧别弹"长按选词"
```

- `cursor` 用 `dragging` state 驱动（渲染输出，必须触发重渲染；与高频 `offset` 走 ref 是两码事）。
- `user-select` 整个画布禁 —— 画布上没有需要选中的东西（节点是按钮，连线是 svg）；要复制文字请到**底部详情面板**，那里正文可选（面板不在画布容器内）。
- **节点 `onClick` 与画布拖拽不冲突**：节点上 `onPointerDown={(e) => e.stopPropagation()}` 阻断冒泡，拖节点不会平移画布；点节点位移为 0，画布分支走 `onBackgroundClick` 判定的前提是"点在了画布背景上"。

### 影响范围

`src/components/lab/CanvasStage.tsx`（容器样式 + 拖拽分支）。

### 验证

```

PASS  缺陷4：画布禁止选中文字（user-select: none）    userSelect=none webkit=none
PASS  缺陷4：拖拽过程中光标变为 grabbing              拖拽中=grabbing
PASS  缺陷4：松手后光标恢复 grab                     松手后=grab
```

### 6.1 中途发现并修掉的一个**测试自身**的假通过（如实记录）

第一次跑修复后的生产构建，结果是 **113/118**，报 5 条失败。逐条查下来，**根因在测试脚本，不在产品** —— 但其中一条属于"假通过"，必须点名：

- `reset_volatile_state()`（脚本前置）只清了 `Surgery`，**没清 `Relation`**。
- 而验收 11 会真跑一次「运行演化分析」→ 写 `Relation`。
- 于是**第二次跑**时：`Relation` 残留 2 → 演化视图**不再是空态** →「运行演化分析」按钮（只在空态渲染）压根不出现 → 11.2「空态主按钮存在」失败。
- 更糟的是：11.3 的断言写死 `before_rel = 0`，于是 `after_rel(2) > before_rel(0)` **凭空通过** —— 明明一下都没点到按钮，却报"Relation 被写入"。

> 这正是产品负责人警告的**"用'通过'掩盖没做的事"**。一条失败、一条假通过，指向同一个"前置没清干净"。

**修法（两处，都在测试侧）**：

1. 前置同时清 `Relation`（它和 `Surgery` 一样是脚本自己会写的**易变**数据）；
2. `before_rel` 改成**从库里读真值**，不再写死 0 —— 单一事实来源，杜绝"残留冒充写入"。

修完后：**119/119，且可重复跑**（`relation 0 → 2` 的 0 是真实读出来的）。产品代码一行没动。
